# 01 · Account-Matrix Operations

Running dozens to hundreds of game accounts is a logistics problem before it is a gaming problem. The matrix works when every account has a defined role, a schedule, and a ledger.

## Structure

- **Cohorts, not chaos.** Group accounts into cohorts by start date and strategy (e.g., 20–30 per cohort). A cohort shares a playbook version, a cost basis window, and a review date.
- **Roles inside a cohort.** Front-line accounts push progression; support accounts feed resources and market liquidity; reserve accounts stay clean for late-campaign opportunities.
- **One operator, one board.** A single tracking sheet is the source of truth: account, cohort, role, cost in, value out, status. If it isn't on the board, it doesn't exist.

## Scheduling

- Campaigns run on the game's calendar (seasons, events, snapshot rumors), not on operator convenience. Build the week around announced events; leave slack for emergency windows (surprise snapshots, short claim periods).
- Batch repetitive actions into fixed blocks. Context-switching is the hidden tax on matrix operations.

## Record-keeping

- Log **cost in** the day it happens (gas, items, fees, time-priced labor) — reconstruction later is fiction.
- Mark-to-market weekly, in the settlement currency, whether you like the number or not.
- Archive dead accounts with a one-line cause of death. The archive is where next season's playbook comes from.
